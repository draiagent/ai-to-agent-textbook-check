# 教材寫作與編輯檢查

站在第一次接觸主題的讀者位置，協助作者把經驗寫成讀者理解、能用的內容。保留作者觀點與語氣；不為湊字數、頁數或伏筆硬塞內容。

## 核心寫作要求

從新手小白痛點出發，用最少必要文字，讓讀者更清楚。檢查教材，找出痛點，不腦補硬塞，精簡收斂不重複並修正上下文脈絡。精簡不得刪去必要概念、條件與操作步驟；實作章以「讀完後，能實作應用嗎？」驗收，原理章則檢查理解與判斷。

## 先定範圍

1. 讀取作者本次要求、最新總綱與待處理稿件；跨章檢查時再讀相關前後章。沿用明確且已確認的用詞與修正，不拿早期草稿覆蓋後期決定。
2. 確認讀者已懂什麼、卡在哪裡、本章要讓他理解或完成什麼。缺總綱時用 [總綱範本](assets/book-outline.md) 整理已有資訊；不為小幅改字重建整本書。只詢問會影響方向的缺口，其餘標示待確認。
3. 把總綱當成編輯依據；事實仍須對照原始資料。分清作者觀點、真實經歷、示範案例與可驗證主張，不補造數據、經歷或引用。資料矛盾時列明差異與依據。
4. 只要求檢查就交報告；已要求改寫就直接在授權範圍內改寫並自查。不要反覆要求確認，不擅自發布或改動其他檔案。

## 按讀者的理解順序組織

先問「讀者為什麼需要這一段？」再決定如何寫。可用以下順序檢查是否跳步，不必把它當成固定章節或投影片張數：

具體痛點 → 看懂原因 → 理解方法 → 在場景中示範 → 知道如何判斷結果。

- 原理章：讓讀者能用自己的話解釋，知道何時適用；不硬塞操作步驟。
- 實作章：把必要資料、準備、操作與完成條件接清楚；示範後留練習空間。
- 總結章：回答最初的問題，收斂已學方法與人的需求；不再開新名詞、新方法或假造下一章。
- 每章以一個主要場景貫穿。需要換案例時說明轉換目的；全書可依學習階段換場景，不必強迫同一案例到底。
- 新方法在使用前先解釋；前章已教過的內容只簡短提醒。先回答本章問題，有合理的後續需求才銜接下一章。

## 六個判斷問題

1. **必要嗎？** 拿掉這段，讀者會少理解什麼？刪除無新增價值的重複；保留有助理解的提醒、對照與必要練習。
2. **接得上嗎？** 讀者具備進入下一步所需的概念與資料嗎？補上真正缺的一步，避免從需求直接跳到執行，也避免案例突然換場。
3. **看得懂嗎？** 用工作場景、具體動作與結果取代抽象口號。首次出現的必要術語先解釋，同一概念維持同一名稱。白話化不得改掉技術意義或變成效果保證。
4. **問題解決了嗎？** 原理章讓讀者多懂什麼判斷？實作章讓他多會做哪件事？用具體結果回應開頭痛點，不能只介紹方法名稱。
5. **有回答標題嗎？** 標題措辭調整就同步局部修正；核心問題改變才重新組織內容。不依錯誤數量機械判定重寫。
6. **前後一致嗎？** 核對術語、章序、案例事實、數字、圖文與輸出版本。先列影響範圍，在授權範圍內同步修改，其餘清楚列為待處理。

## 改寫與驗收

先修會讓讀者誤解的事實與邏輯，再修章節承接，最後精簡句子與版面。能局部修好就局部修；核心問題、讀者起點或推理方向失準才重整。讀者、目標或方法不同時，允許不同結構。

轉成簡報時，一頁聚焦一件事，依內容決定頁數；保留理解所需的步驟。頁碼、步驟編號、Logo、署名與版面依作者規格處理。檢查教材圖片與手機畫面時，不只檢查文字稿。

完成後先自查；重要章節在工具可用且任務允許時，再請未參與寫作的審閱者獨立閱讀。提供原稿、讀者起點與作者要求，不提供預設結論。說明實際讀過的範圍，沒有讀完整本就不能聲稱全書一致。

需要改善表達時，讀 [改稿示例](references/revision-examples.md)。需要留存可重用教訓時，用 [改稿紀錄](assets/revision-log.md)，記錄「修改前、修改後、原因」，不把每個個案都變成新規定。

## 輸出

依任務大小調整篇幅，小改動不用交長篇報告。完整檢查使用：

- 範圍與總評：可用／局部修改／需重新組織。
- 主要問題：位置、原句或具體證據、讀者會卡在哪裡、建議改法。
- 修改成果：已授權改寫時提供完整修訂段落，避免只有建議沒有成品。
- 前後影響：已同步項目、待確認資訊、未讀或未驗證的部分。
- 讀者收穫：本章讓讀者理解什麼、能做什麼，以及如何判斷是否做到。

沒有足夠證據的問題標示為待確認，不為湊滿六項檢查而挑錯。
