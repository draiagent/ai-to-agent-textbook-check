# 改稿示例

以下為示範句，不是已發生的企業案例或成效實測。依讀者與上下文判斷，不照抄句型。

## 把抽象好處寫成具體工作
修改前：建立一致的輸出規格，提高交付效率。
修改後：先把表格欄位和排列順序講清楚，再請 Agent 按這個格式交付並檢查，減少每次重新排版的工作。
理由：交代做什麼、怎麼做、解決什麼；不保證每次都正確。

## 補上缺的一步
修改前：整理影片需求，接著把任務圖卡交給 Agent。
修改後：先整理影片用途、素材與交付要求，把工作步驟和檢查方式寫進任務圖卡，再交給 Agent 執行。
理由：讀者還不知道圖卡怎麼來，必須先交代如何建立。

## 統一概念，不為換詞而換詞
修改前：用 VSA 任務圖卡固定風格，再用 VAC 設計圖卡安排工作。
修改後：用 VSA 設計圖卡說明風格，再用 VAC 任務圖卡安排工作。
理由：在這本教材中兩個名稱各有用途，不能互換；其他書依自己的術語表。

## 讓後續問題自然出現
修改前：下一章將帶你邁向更強大的智慧未來。
修改後：風格確認後，怎麼把這次用得好的素材與設定留下來，讓下次能直接沿用？
理由：只有下一章確實處理素材與知識保存時，這個銜接才成立。

## 局部改字不必重寫
作者只把「設計任務」改為「任務設計」時，核對適用範圍內的名稱與目錄即可；若作者把章節主題由訂單改為影片製作，才需要檢查案例、步驟與下一章的承接。

## 提醒不等於重複
實作章再次提醒「Agent 也要檢查工作」，若接著說明這次要檢查字幕時間與輸出格式，就有新的用途；若三張投影片只是同義重述，應合併。
